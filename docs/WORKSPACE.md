# StockHale workspace and offline operation

Run on Node 24+ with PostgreSQL, using Neon's pooled DATABASE_URL in Vercel. Set BETTER_AUTH_SECRET and BETTER_AUTH_URL, then run `pnpm db:migrate` before deployment. Better Auth manages users, password hashes and 7-day sessions in the shared database. New instances and deployments do not depend on local files. HTTPS sessions use Secure, HttpOnly, SameSite=Strict cookies. Write endpoints require the exact configured Origin. Authentication attempts are rate limited by account email in Postgres. Database session validation keeps sign-out and expiration authoritative across instances. See [setup, deployment and legacy SQLite import](../README.md).

Sign up creates an owner workspace. Owners use Settings to change store name, choose an optional PNG/JPEG/WebP image up to 500 KB, and Add a team member by assigning an email and at least one module. Share the generated `/team-sign-up` link, valid for seven days, with that member. They enter the assigned email and create their own password. Setup links cannot be reused or used with a different email; adding the same pending email again replaces the previous link and permissions. Owners can change assigned modules after signup. Members land directly in an assigned module and see only authorized navigation and module actions; Settings and Notifications remain owner-only. Owners cannot remove their own authority. Existing accounts cannot join a second workspace in this implementation. Assigned modules grant navigation and server-enforced write authority; the retail dataset is shared with workspace members for cross-module stock, contact and billing calculations. This is not row-level data isolation.

The owner can import previous stockwell.retail.v1 browser records into an empty workspace from Settings. The original browser copy is retained.

After a successful online sign-in, the workspace is cached on this device. Each edit persists its UUID, actor session context, action time, module, and resulting records before it appears saved. In production, the service worker preloads the app shell, initial scripts/styles, their fonts, and the invoice PDF font, then caches subsequent static assets. Development disables offline asset caching. Previously loaded workspaces can open and edit during internet or server interruption. First sign-in/sign-up, adding members and owner permission/profile changes require the server. Cached modules remain usable offline; updated authority applies when the device reconnects. Device cache should be used only on trusted devices.

The queue retries every 5 minutes while the tab is visible, on reconnect, and when the tab becomes visible again. Server changes are committed transactionally, once per event ID. Server revisions prevent lost updates: concurrent changes block the queue with an explicit conflict. Export pending changes to JSON before loading current server records; loading server records discards the pending local queue after confirmation. No automatic merge of financial records. Permission revocation and expired sessions preserve the queue for resolution. Signing in again preserves queued changes for that workspace. Sign-out requires a fully synced queue, revokes the server session, and clears that workspace's local cache. Closing a browser leaves pending edits cached.

Every accepted record change and owner settings change creates an audit event recording actor name/email, module, action, changed record IDs and fields, client action time and server receipt time. Owner notifications and logs update during sync/polling, with a New indicator and read acknowledgement. The UI shows the latest 300 events; the server retains full history. Offline changes notify the owner only after they reach the server.

Set RESEND_API_KEY and RESEND_FROM (a Resend-verified sender) in .env.local or deployment secrets. Recipients are the workspace owner's registered email. Keys never enter client bundles. Record-change notifications are grouped into one plain-text daily digest per workspace using the time zone selected in Settings. A scheduled Cloudflare Worker checks each workspace every five minutes and sends the digest at or shortly after 11:58 PM local time, with each audit row listed separately. Authenticated API activity also drains due messages as a fallback. Accepted-by-provider messages show sent (not a delivery receipt). Failures remain in a persistent outbox with exponential retries and a stable idempotency key. Plan renewal reminders retain immediate delivery. Actual email delivery requires configured credentials and a verified domain; this environment did not send real emails.

USB/Bluetooth barcode scanners use keyboard mode and an Enter or Tab suffix. Product, purchase, billing and return forms focus the barcode input when opened. Scanning fills a product barcode, adds a matching purchase/bill line (repeated scans increase quantity), or selects the return product from the chosen original transaction. Enable **Use barcode scanner** in the form to route scans to the barcode input even when another field is focused. While scanner mode is on, keyboard input is reserved for scanning; turn it off or press Escape before typing into other fields. Scanner mode does not save a transaction automatically. Lookup and scanner input work without a network connection after online workspace setup.

Billing supports a walk-in customer without a saved profile, or a company customer. Company profiles require only the company name; phone, email, address and NTN are optional. A supplied NTN is retained offline and included in customer search, invoice previews and downloaded invoices. Walk-in bills must be paid in full; credit remains tied to a saved customer profile.
